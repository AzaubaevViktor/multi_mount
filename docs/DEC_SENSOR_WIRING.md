# MPU6050 + QMC5883L на DEC Arduino Nano

Прошивка рассчитана на классический **Nano ATmega328P, 16 МГц, логика 5 В**
(`telescope_dec/platformio.ini`, среда `nanoatmega328`). QMC5883L — устройство
на `0x0D`; HMC5883L и другие варианты QMC имеют другой протокол и этим драйвером
не поддерживаются. MPU6050 автоматически ищется на `0x68` и `0x69`.

## Провода

Оба датчика используют одну I²C-шину. Для обычных модулей с логикой 3.3 В
подключение через двунаправленный преобразователь уровней I²C:

| Nano / преобразователь | MPU6050 | QMC5883L |
|---|---|---|
| A4 → HV1; LV1 на стороне 3.3 В | SDA | SDA |
| A5 → HV2; LV2 на стороне 3.3 В | SCL | SCL |
| GND, общая земля всех плат | GND | GND |
| Питание датчиков, см. ниже | VCC / 3V3 | VCC / 3V3 |
| GND | AD0: адрес 0x68 | — |
| Не подключать | INT, XDA, XCL | DRDY / INT |

HV преобразователя → Nano 5V; LV → стабилизированные 3.3V.
SDA и SCL должны иметь внешние подтяжки к питанию **каждой стороны**
преобразователя, типично 4.7 кОм. Часто они уже стоят на преобразователе
и модулях: проверьте схему конкретных плат, не добавляйте их вслепую параллельно.
Внутренние подтяжки Nano к 5 В в прошивке отключены.

Питание голых чипов — стабилизированные 3.3 В. На модуле пин VCC может быть
входом встроенного стабилизатора, которому нужны 5 В, либо непосредственным
питанием чипа. **Без модели / схемы модулей нельзя назначить одинаковое
напряжение их VCC.** Регулятор питания на плате сам по себе не делает SDA/SCL
совместимыми с 5 В. Для модулей с подтверждённым преобразованием уровней
дополнительный преобразователь не нужен.

Если AD0 подключён к питанию логики MPU6050, адрес станет 0x69; прошивка
поддерживает этот вариант. Нельзя подавать на AD0 5 В непосредственно.

### Обязательная перестановка индикатора

Раньше A5 управлял синей частью индикатора режима. В новой прошивке она
перенесена на **A0** (через существующий токоограничивающий резистор).
Переставьте этот провод **до** подключения SCL. Это изменение внесено и в
диагностическую прошивку `wirescan`.

Остальная распиновка сохранена:

| Назначение | Пины Nano |
|---|---|
| STEP / DIR / EN | D7 / D4 / D12 |
| UART TMC2209 RX / TX | D8 / D9 |
| Индикатор питания / измерение напряжения | D11 / A1 |
| RGB шагов | D6 / D5 / D3 |
| RGB режима | A3 / A2 / **A0** |
| Датчики SDA / SCL | **A4 / A5** |

## Крепление и данные

Обе платы закрепите жёстко на одной части трубы. Положительные направления
**X, Y, Z чипов** должны совпадать: ориентация надписей / краёв плат не всегда
соответствует осям чипов. Драйвер передаёт обе тройки в этой общей системе.
Поворот всего узла относительно трубы учитывается точками калибровки в Python;
независимый поворот магнитометра относительно акселерометра этим не исправляется.

Магнитометр разместите как можно дальше от мотора, силовых проводов, магнитов
и стального корпуса. Закрепите его в конечном месте до калибровки по plate solve.
Калибровка по точкам не гарантирует исправления изменяющегося поля от мотора.

MPU6050: диапазон ±2g, фильтр акселерометра 10 Гц. Его specific force
инвертируется, чтобы по контракту вектор гравитации указывал **вниз**;
передача — 0.001 м/с². Во время движения / вибрации это ещё и линейное ускорение,
поэтому точки калибровки снимайте после остановки и успокоения трубы.
Гироскоп и температура в текущий протокол не входят.

QMC5883L: continuous, 50 Гц, OSR512, ±2 Gauss, передача 0.01 мкТл.
Насыщение ADC и OVL отвергаются. Фактическая частота пар ниже ODR чипов:
асинхронный опрос выполняет одну регистровую операцию за раз с паузой 20 мс,
чередуя датчики; status читается до данных. За один loop исполняется максимум
один шаг I²C-автомата, без ожиданий; при STEP HIGH опрос пропускается.
Каждая транзакция ограничена 20 мс, включая STOP. Таймаут сбрасывает периферию
TWI, затем продолжается обнаружение. Постоянно замкнутая линия останется
недоступной до устранения неисправности, но не удерживает цикл DEC в ожидании.

| Состояние | Что получает Python |
|---|---|
| Датчиков нет | `device_not_found`, без векторов |
| Обнаружен чип, но ещё нет гравитации | `no_data`, без векторов |
| Только MPU6050 / магнитометр отказал, переполнен или устарел | Гравитация; `heading_unavailable`, без Alt/Az и RA/DEC |
| Оба дают новые измерения | Гравитация + магнитное поле; координаты после калибровки в Python |
| MPU отвечает, но перестал обновлять данные | Возраст растёт; Python отклоняет `stale_data` |

По команде `sensor` возвращается кэш, I²C-транзакция в обработчике команды
не запускается. Калибровка, количество точек и файлы остаются в Python.
Магнитометр без MPU6050 не публикуется отдельно: текущий контракт требует
гравитацию для доступного измерения.

## Сборка и проверка

```sh
python -m platformio run -d telescope_dec -e nanoatmega328 -e wirescan
c++ -std=c++11 -O1 -Wall -Wextra -Werror -fsanitize=address,undefined \
  -o /tmp/orientation_sensors_selftest telescope_dec/test/orientation_sensors_selftest.cpp
/tmp/orientation_sensors_selftest
```

Образ для DEC: `telescope_dec/.pio/build/nanoatmega328/firmware.hex`.
HELLO: `protocol=3`, `firmware=4`. Существующий протокол Python совместим.
Входной буфер команд уменьшен до 128 байт (127 символов + NUL); самая длинная
поддерживаемая v3-команда с аргументом занимает 20 байт вместе с LF.
TX-кольцо и механизмы проверки / ошибок протокола сохранены.

Перед эксплуатацией нужна стендовая проверка на реальных платах: сначала
без движения проверить отсутствие, сырые векторы, ориентацию и отключение
датчиков; затем проверить временные интервалы STEP при опросе и отказах шины.
Хостовые тесты и сборка не измеряют джиттер реального мотора.
